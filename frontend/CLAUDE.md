# JobFit Frontend

NextJS app built as a static export (`out/`) and served by the FastAPI backend at `/`.
The Dockerfile builds it and copies `out/` into the backend `static/` directory.
Read `AGENTS.md` first: this NextJS version differs from older training data; its docs are in `node_modules/next/dist/docs/`.

## Stack

- NextJS 16 (App Router, `output: "export"`), React 19, TypeScript, Tailwind CSS 4 (via `@tailwindcss/turbopack`, no PostCSS config)
- Vitest + React Testing Library (jsdom) for unit tests
- Playwright for end-to-end tests against a throwaway container (`http://localhost:8001`)

## Layout

- `app/` - root layout, `page.tsx` (home), `globals.css` (theme tokens)
- `app/page.tsx` renders the client `App`: `ClerkProvider` (`@clerk/react`, Core 3) with `<Show when="signed-out">` -> `<SignIn routing="hash">`, `<Show when="signed-in">` -> `Header` (`UserButton`) + `Workspace`
- `components/Workspace.tsx` - owns user data and chat state, including `generated` (`Generated`: the resume `versions`, the `selected` one and the Pro verdict), built by `generatedFrom(result)`: one version, or one per Pro candidate (best first, with its own model in `settings` and its `review`); each version has the edited content and the `settings` (`GenerationSettings`, picked with `generationSettings`) that generated it; a new AI resume replaces it all. Each `pro.failed` entry adds an `info` chat note (`failureNote`) before the AI reply. Edits go to the selected version; a download adds the Pro fields (`pro_judge_model`, `pro_rank` = selected + 1, both null when unjudged) only for Pro results; loads baseline, history and preferences on mount (`baseline` is `undefined` while loading; `ResumePanel`, like `PreferencesPanel`, renders only once loaded so it can pick its initial open state), saves through `lib/api.ts` (preference changes are saved one after another in a promise chain, and each chat turn awaits it so the backend reads the latest preferences), sends chat turns to `/api/generate` (history kept client-side). Before each turn it adds an `info` chat entry built by `settingsNote(prefs)` (model, optimization level label, tone or "no preference", notes only when set, in Pro mode "Model: <id> (chat and judge)" and "Pro models"; not the experience years; one per line, rendered with `whitespace-pre-line`); `busyText(prefs)` is the chat's waiting text (longer in Pro mode); `info` entries are filtered out of the history sent to the AI
- `components/` panels take props only: `PanelTitle` (shared `h2` whose title button toggles a panel, `aria-expanded`, rotating chevron; used by the three collapsible panels, each keeping its own `open` state), `ResumePanel` (upload .md/.txt; starts collapsed when a baseline is saved), `JobDescription` (pasted text), `CustomResume` (`CustomResumeData` is company, content, `settings` and an optional Pro `review`; once there is a resume, its header has a "PDF style" select (`STYLES` from `lib/api.ts`) left of the Markdown / Preview toggle, reporting changes through `onStyleChange`, which `Workspace` saves as the `style` preference; with a `pro` prop (`ProView`) it shows a `tablist` of candidates labelled by `candidateLabel` (model, score, "best", issue count) and an open `details` "Why it won (judged by ...)" or "Not compared" with the rationale and the selected candidate's strengths, weaknesses and a "Rule violations" list; Markdown / Preview toggle, `aria-pressed` buttons: editable textarea, or the backend HTML in a sandboxed iframe titled "Custom resume preview", re-rendered when the text or PDF style changes; Download PDF sends the edited text), `HistoryPanel` (starts expanded; company, time and a wrapping line of `historyDetails(entry)` labels: model, optimization label, Professional/Earlier years, max pages, tone, notes when set, "Pro: judged by <model>, rank <n>" for a judged Pro download, each truncated with a `title`; null settings of older rows are left out; re-download links; "Clear history" header button, only with entries, confirms with `window.confirm` then calls `onClear`; above `MAX_VISIBLE` (10) entries the list's max height is set in a layout effect to the measured bottom of the 10th row, since rows can wrap, and it scrolls), `PreferencesPanel` (controlled: `prefs` come from `Workspace`, each change calls `onChange` with the full preferences and `Workspace` saves and passes them back, so a style set in `CustomResume` is never overwritten by a stale copy; starts expanded; no section label, just the resume generation settings: AI model, Pro mode (`ProModeFields`: checkbox; when on, a "Pro models (2-4)" checkbox group; no judge setting, the AI model judges. The controls only allow valid states: the last 2 candidates and the AI model's checkbox (labelled "(AI model, judges)") are disabled, unchecked ones are disabled at 4, in Pro mode the AI model select lists only non-candidates, and turning Pro mode on applies `proModelsWithout(model, pro_models)` (drops the AI model, tops up to 2 in `MODELS` order); candidates are kept in `MODELS` order), optimization level (select with the chosen level's description as `aria-describedby` text), Professional/Earlier Experience years, max pages, tone, notes, include phone and include graduation year checkboxes; no Save button), `ChatSidebar` (conversation, Generate button, message box, `busyText` while waiting; buttons disabled until preferences load); plus `Header`, `HealthIndicator`
- `lib/api.ts` - typed data calls, `MODELS` (selectable models, default first; keep in sync with `Model` in `backend/app/ai.py`), `PRO_MIN_MODELS`/`PRO_MAX_MODELS` (2/4, as the backend), `ProCandidate`/`ProFailure`/`ProResult` (the `pro` part of `GenerateResult`), `ProFields` (history's `pro_judge_model`/`pro_rank`), `OPTIMIZATION_LEVELS` (value, label, description; keep in sync with `Optimization` in `backend/app/routes/preferences.py`) and `optimizationLabel`, `GENERATION_KEYS` / `GenerationSettings` (the preferences that shape a resume; keep in sync with `GenerationSettings` in `backend/app/routes/preferences.py`), `generationSettings`, `toneLabel`, `ChatEntry` (chat message or `info` note), `generate`, `pdfUrl`, `previewHtml`, `downloadCustomResume` (records history including the generating model, then downloads), `clearHistory` (`DELETE /api/history`, 204 so it bypasses the JSON `request` helper)
- `tests/` - Vitest unit tests (`*.test.{ts,tsx}`), `setup.ts`, `fetchMock.ts` (stub fetch by "METHOD /path"; status 204 returns no body)
- `e2e/` - Playwright tests (`*.spec.ts`); `global.setup.ts` runs `clerkSetup()` and creates the two Clerk test users if missing; `helpers.ts` (`signIn`/`signOut` via `@clerk/testing`, `ALICE`, `BOB`, `showBaseline` to expand the baseline panel before checking its text); `generate.spec.ts` mocks `/api/generate` with `page.route` (no AI cost; its Pro mode test turns Pro mode off again at the end, since preferences persist for the shared test user); `preferences-live.spec.ts` is the one test that calls the real AI (about 15-60 s) to prove saved preferences (phone, experience windows) reach the model

## Rules

- Static export only: no server actions, no API routes, no SSR-only features
- All data comes from the backend via same-origin `/api/*` calls; Clerk's `__session` cookie authenticates them (no Authorization header needed)
- Use `@clerk/react`, not `@clerk/nextjs` (which needs a Next.js server). Core 3 replaced `SignedIn`/`SignedOut` with `<Show when=...>`
- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` is inlined at build time (Docker build arg from `.env`); unit tests mock `@clerk/react`
- Clerk components are themed via `appearance.variables` in `App.tsx`. On this dark theme `colorNeutral` must be light (`#F1F5F9`): Clerk defaults it to black and derives menu item text, borders and hovers from it, which made the account menu unreadable. `e2e/account-menu.spec.ts` guards this with a WCAG contrast check (>= 4.5)
- Use Tailwind theme tokens, not raw hex: `canvas` `#090D16`, `surface` `#111827`, `line` `#1E293B`, `primary` `#38BDF8`, `accent` `#F59E0B`, `ink` `#F1F5F9`
- Keep components small and simple; no emojis
- In unit tests, stub `fetch` with `vi.stubGlobal`; globals and `vi.spyOn` spies are restored after each test in `tests/setup.ts`. jsdom has no layout, so layout (e.g. the history scroll cap) is checked in e2e

## Commands

- `npm run dev` - local dev server (API calls need the backend running)
- `npm run build` - static export to `out/`
- `npm test` - unit tests
- `npm run test:e2e` - e2e tests; Playwright builds the image and runs a throwaway `jobfit-e2e` container on port 8001 (empty db, never touches `data/`), one worker since tests share the single user
- `npm run lint`
