# The Resume Customizer MVP web app

## Business Requirements

This project is for building a resume customizer App, which allows the user to customize a baseline resume for a specific job description. The app name is JobFit. Key features:
- A user can sign in (Clerk accounts; each user only sees their own data)
- When signed in, the user can upload or update the baseline resume, paste the job description, generate the custom resume, and optionally download this as PDF
- The generated custom resume is editable in the UI; Download PDF always uses the edited text, and that edited text is what is saved to the database
- The main column shows, top to bottom: Baseline resume, Job description, Custom resume, Preferences, Download history; the AI chat is a sidebar on the right
- When expanded, the Baseline resume panel shows a note: "Use a format the AI can easily understand, such as Markdown (.md): headings for sections and a list item per bullet." (uploads accept .md and .txt)
- The Baseline resume, Download history and Preferences panels expand and collapse by clicking their title (chevron). Baseline resume starts collapsed when a baseline is already saved (expanded otherwise; uploading does not change it); the other two start expanded. The open/closed state is not persisted. The Upload resume and Clear history buttons stay in the panel headers while collapsed
- A Markdown / Preview toggle switches the custom resume between the editable Markdown (default) and a read-only preview rendered by the backend from the same HTML and saved PDF style as the PDF; the preview follows edits and PDF style changes
- The baseline resume and user preferences (PDF style, AI model, Pro mode with its Pro models, optimization level, tone, max pages, notes for the AI, include/exclude phone number, include/exclude university graduation year, include/exclude volunteering, Professional Experience years, Earlier Experience years) are persisted
- The Preferences panel holds the resume generation settings, with no section label, in this order: AI model, Pro mode (with Pro models when on), optimization level, tone, notes for the AI, Professional/Earlier Experience years, include phone number, include graduation year and include volunteering (side by side, wrapping when narrow), max pages. The PDF style (professional, modern, classic) is a select in the Custom resume panel header, left of the Markdown / Preview toggle (shown once a resume is generated); it is still a saved preference, used by the preview and the download
- Preferences are saved automatically on every change (there is no Save button) and sent to the AI with the baseline resume and job description on every generation; a generation waits for pending preference saves. Unchecking "Include phone number in generated resume" removes the phone number from the generated resume. "Include university graduation year in generated resume" is off by default, so Education entries have no year; checking it keeps each degree's graduation/completion year from the baseline
- "Include volunteering when the job mentions volunteering or work-life balance" (preference, on by default): when on, the AI includes the baseline's Volunteering section only if the job description specifically mentions volunteering or work-life balance; when off, never. The AI keeps the resume within the max pages preference (turned into a word and line budget, since models cannot judge PDF pages). When over the limit it fits the resume in this order, stopping once it fits: leave out Volunteering, put the contact details on one line and the tools and languages on one line (" | " separated), leave out Earlier Experience, then shorten within sections; only those two sections may be left out to fit
- Optimization level (dropdown, default "Smart integration"; each option is the level name followed by a short summary: "Light polish - adds the job's skills, keeps your wording", "Smart integration - weaves the job's skills into your work history", "Full tailoring - rewrites and reorders the content for the job"; the chosen level's longer description shows under it; the chat note and history show the name only) sets how much the AI changes the resume: "Light polish" adds the job's skills and requirements to the summary and skills and copies the work history bullets word for word (it may leave out the least relevant bullets to fit the page limit, never rephrase them); "Smart integration" naturally works them into the work history; "Full tailoring" fully rewrites and reprioritizes the content for the employer. Every level still follows the resume rules (no invented facts). Stored as `light`, `smart`, `full`
- Pro mode (off by default): the "AI model" still handles the chat and clarifying questions, and also judges the Pro models (there is no separate judge setting). In Pro mode it writes no resume itself (a separate prompt, `build_pro_chat_prompt`, with the same steps, rules and context, asks only for `{reply, ready}`): it asks questions or says it is ready. When ready, the 2 to 4 "Pro models" (default `anthropic/claude-haiku-5.5`, `anthropic/claude-sonnet-5.5`; in Pro mode never the AI model, enforced by the UI and the backend: the AI model's Pro checkbox is disabled and marked "(AI model, judges)", the AI model list leaves out the Pro models, and turning Pro mode on drops the AI model from the Pro models, topping up to 2) each write one in parallel from the same conversation, told to write now without questions; a candidate that fails, times out (300 s) or returns no resume is dropped, and the chat shows a note for it before the reply: "<model> did not return a valid resume (<reason>), so it was left out." (reason: "timed out after 300 s", "failed with an error" or "returned no resume"). The AI model, as judge, ranks the candidates against the baseline, job, preferences and resume rules, seeing them only as A-D in shuffled order (the judge's schema allows only the labels in use; without that `gpt-oss-120b` ranked a non-existent candidate in 2 of 3 runs): a score out of 10, strengths, weaknesses and rule violations each, plus a rationale. With one candidate left there is no judging; with none the reply says so and no resume is shown. The chat reply names the winner and its score; the Custom resume panel shows one tab per candidate (model, score, "best", issue count), the winner selected, and a collapsible "Why it won" with the rationale and the selected candidate's review; each tab keeps its own edits, and Markdown/Preview and Download apply to the selected one. A Pro turn takes a short ready check, plus the slowest candidate, plus the judge, and costs one generation per Pro model plus the ready check and the judge (measured per resume: from $0.0007 with gpt-oss-120b to $0.09 with Opus 5.5)
- Experience windows: roles that ended within the last "Professional Experience (years)" (default 15) go in a "Professional Experience" section with full detail; roles that ended in the "Earlier Experience (years)" before that (default 10) go in an "Earlier Experience" section with one list item per role (role, company name and years only, no other details); older roles are left out. A role is placed by its end year; 0 earlier years means no Earlier Experience section
- The custom resumes are persisted when downloaded. The company, PDF style, download timestamp and the generation settings the resume was made with (model, optimization level, Professional/Earlier Experience years, max pages, tone and notes for the AI; the values used at generation, not the ones selected at download time; for a Pro candidate the model is the candidate's) are also persisted, and for a judged Pro candidate the judge model and its rank (1 = best).
- The PDF file is named `Resume - <name> - <company>.pdf` (set by the backend via `Content-Disposition`). The name is the custom resume's first `# ` heading; the company is the one the AI extracted ("Unknown company" when it returns none). Characters not allowed in file names are replaced and whitespace collapsed; an empty part is left out
- The user has an option to see the custom resume history (company and download time, with a line of the generation settings under them: model, optimization level, "Professional: <n> yrs", "Earlier: <n> yrs", "Max pages: <n>", "Tone: <tone>" ("no preference" when empty) and "Notes: <notes>" (only when not empty, truncated with the full text on hover) and, for a judged Pro candidate, "Pro: judged by <model>, rank <n>"; settings not recorded for older downloads are left out), and be able to re-download the PDF for any of these. The list shows at most 10 entries; with more, it gets a vertical scrollbar. A "Clear history" button in the Download history header (shown only when there are entries) asks for confirmation, then deletes all of the user's history entries from the database and empties the list; if the delete fails the list is kept and an alert says so
- AI model preference: `openai/gpt-oss-120b` (default), `anthropic/claude-opus-5.5`, `anthropic/claude-haiku-5.5`, `anthropic/claude-sonnet-5.5`, `openai/gpt-6-sol`, `openai/gpt-5.4-nano`, `google/gemini-3.8-flash`, `google/gemini-4-argon`. The saved model generates the resume. Saved preferences naming a model since removed from the list load with the default AI model, and without it in the Pro models (topped up to 2). Before each prompt it sends, the chat shows a note with the settings used, one per line: "Model: <id>", "Optimization level: <label>", "Tone: <tone>" ("no preference" when empty), "Notes: <notes>" (only when not empty); in Pro mode the first line is "Model: <id> (chat and judge)" and a last line "Pro models: <ids>" is added. While waiting, Pro mode says the turn can take a few minutes. The experience years are not shown in it (they still go to the AI). The note is not sent to the AI
- There is an AI chat feature in a sidebar; the AI is able to ask clarifying questions before generating the final custom resume. A "Generate custom resume" button starts it once a baseline and job description exist. A "Clear conversation" button in the AI assistant header (shown only when there are messages, disabled while waiting for a reply) empties the chat without confirmation; the conversation is client-side only, so the next message starts a new one with the AI. The generated custom resume is kept

- Subscription plans (Clerk Billing, per user; details and cost reasoning in `docs/PLAN.md` Step 12): Free (default, `free`): 5 resumes a month; Basic (`basic`, $10/month): 50 a month and PDF download; Pro (`pro`, $30/month): 200 a month, PDF download, premium models (`anthropic/claude-opus-5.5`, `anthropic/claude-sonnet-5.5`, `openai/gpt-6-sol`, `google/gemini-4-argon`) and Pro mode. Plans and the features `pdf_download`, `premium_models`, `pro_mode` are defined in the Clerk Dashboard; the monthly limits are in the backend. Only resumes produced count: a normal generation 1, a Pro mode run 1 per Pro model that returned a resume; questions, the Pro ready check and the judge are free; a Pro run needs an allowance for every selected Pro model. Months are calendar months (UTC). The backend enforces everything (403 for a missing feature, 429 for the limit, before any AI call) and the chat shows its message. The app title bar shows "<used> of <limit> resumes this month · <Plan> plan" and a "Plans" button opening Clerk's pricing table, left of the account menu (not in the AI assistant panel); a checkout's Continue reloads the page with the new plan, and closing the Plans dialog refreshes the session token and the plan. Locked controls stay visible: premium models and Pro mode are disabled and marked "Pro plan" (but can be switched off after a downgrade), Download PDF and history re-download are disabled with "PDF download is available on the Basic and Pro plans." After a downgrade history stays listed but PDFs need a paid plan. Subscriptions are managed (cancel, switch) in the account menu's Billing tab or the pricing table

## Limitations

- Runs locally in a Docker container.
- The job description is pasted text only; URLs are not fetched.
- Clerk Billing: USD only, no tax/VAT, no refunds in Clerk; development uses Clerk's test payment gateway, production needs the owner's Stripe account. Upgrades apply immediately, downgrades at the end of the billing period
- The AI follows the resume rules (from `docs/INSTRUCTIONS.md`: no new technologies, no invented experience entries, graduation year only when the preference is on, experience windows, one-line Earlier Experience entries) by prompt only; there is no hard post-check. Real-model tests check these rules, and models occasionally slip (e.g. `gpt-oss-120b` dropped the Education section in about 1 of 10 runs and put the Nokia role ending 2012 in Earlier Experience in about 1 of 10). For a long baseline a 1-page limit is a known limitation (prompt only, by decision): about 3 in 4 runs fit, the fitting order is only partly followed, and some runs drop Education or the summary; at the 2-page default no measured run went over. Under the length budget Light polish dropped the Education section in about 1 of 18 runs. In Pro mode the judge's rule violations are a model's review, not a hard check (it caught a planted invented role in 4 of 4 test runs)

## Technical Decisions

- NextJS frontend, built as a static export (`output: "export"`)
- Python FastAPI backend, including serving the static NextJS site at /; all API routes under `/api`
- Everything packaged into a Docker container (multi-stage: node builds the frontend, python serves it)
- Use "uv" as the package manager for python in the Docker container
- Use OpenRouter for the AI calls via the `openai` SDK. An OPENROUTER_API_KEY is in .env in the project root
- Default model `openai/gpt-oss-120b`; the user can pick another from a fixed list (all support Structured Outputs on OpenRouter). Structured Outputs: `{reply, company, experience_plan, resume_md}`; `/api/generate` adds the generation settings it used (`GenerationSettings`) and, in Pro mode, `pro` (ranked candidates and the judge's verdict; the judge also uses Structured Outputs). The model list lives in `backend/app/ai.py` (`Model`, validated) and `frontend/lib/api.ts` (`MODELS`); keep them in sync
- Use SQLite (stdlib `sqlite3`, no ORM) at `data/jobfit.db`, creating a new db if it doesn't exist; schema in `docs/DATABASE.md`
- Authentication with Clerk: `@clerk/react` in the frontend, `clerk-backend-api` verifies the session cookie in the backend. `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` are in .env
- Billing with Clerk Billing: the backend reads the plan and features from the verified session token (v2 claims `pla`, e.g. `u:pro`, and `fea`, e.g. `u:pdf_download,u:pro_mode`, absent when none); the frontend uses `<PricingTable />` from `@clerk/react`. Clerk's Backend API needs a `User-Agent` header (Cloudflare rejects Python's default with error 1010); billing endpoints are under `/v1/billing/...`
- PDFs are rendered in the backend from markdown with WeasyPrint (styles: professional, modern, classic); the preview (`POST /api/preview`) returns the same HTML, shown in a sandboxed iframe
- Start and Stop server scripts for Mac, PC, Linux in scripts/

## Project layout and commands

- `backend/` - FastAPI app; see `backend/CLAUDE.md`
- `frontend/` - NextJS app; see `frontend/CLAUDE.md`
- `scripts/start.sh` / `scripts/stop.sh` (and `.ps1`) - build and run the app at http://localhost:8000; rerun `start.sh` after code changes, the container does not pick them up otherwise
- Tests: `cd backend && uv run pytest`; `cd frontend && npm test`; `cd frontend && npm run test:e2e` (throwaway container on port 8001, two Clerk test users)
- macOS: backend needs `brew install pango` for WeasyPrint

## Color Scheme

- Background: `#090D16` - Deep obsidian canvas for immersive dark mode
- Surface / Card: `#111827` (Gray 900) - Layered sidebars and card containers
- Primary / Action: `#38BDF8` (Sky 400) - High-visibility interactive elements and links
- Accent: `#F59E0B` (Amber 500) - Secondary highlights (e.g. the Generate button)
- Text Primary:`#F1F5F9` (Slate 100) - Crisp, legible text against dark surfaces
- Border / Divider: `#1E293B` (Slate 800) - Low-profile structural lines
- Clerk sign-in and account menu use the same palette (`appearance.variables` in `frontend/components/App.tsx`); `colorNeutral` is set to the text color so Clerk's menu items stay legible on dark surfaces
