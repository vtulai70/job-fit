# JobFit Backend

FastAPI app that serves the JSON API under `/api/*` and the static NextJS export at `/`.
Written ahead of the code (Step 1); update as code lands.

## Stack

- Python, `uv` for packages and running
- FastAPI + uvicorn
- SQLite via stdlib `sqlite3` (db at `data/jobfit.db`, created if missing)
- WeasyPrint for markdown -> HTML -> PDF
- `openai` SDK (v3, Chat Completions API) pointed at OpenRouter; default model `openai/gpt-oss-120b`, user-selectable
- pytest + FastAPI TestClient

## Layout

- `app/main.py` - app creation, lifespan (creates db), session middleware, routers, static mount
- `app/auth.py` - Clerk session verification (`clerk-backend-api` `authenticate_request`, cookie or Bearer) in `session_claims` (`Claims`, resolved once per request and shared by the user and plan dependencies); `CurrentUser` (Clerk user id) and `UserId` (local db id, row created on first request)
- `app/db.py` - schema (see `docs/DATABASE.md`), `init_db` (also adds the `ADDED_HISTORY_COLUMNS` (generation settings: `model`, `optimization`, `professional_years`, `earlier_years`, `max_pages`, `tone`, `notes`, then `pro_judge_model`, `pro_rank`, with their SQL types) to older `custom_resumes` tables), `connect`, `Db` per-request connection dependency
- `app/plans.py` - Clerk Billing: `Plan` (key, features, `has`, `limit`) from the token claims (`plan_from_claims`: `pla` without its `u:` scope, default `free`; `fea` comma-separated, absent when none), `CurrentPlan` dependency (`current_plan`), `MONTHLY_GENERATIONS` (`free` 5, `basic` 50, `pro` 200; an unknown plan gets the free limit), usage in the `generations` table (`used_this_month`, `record_generations`, calendar months in UTC, `utc_now` patched in tests), `GET /api/plan` (`{plan, features, limit, used, resets_at}`)
- `app/routes/resume.py` - `GET/PUT /api/resume/baseline`
- `app/routes/history.py` - `GET/POST/DELETE /api/history` (DELETE removes all of the current user's entries, 204; POST and the PDF route need the `pdf_download` feature, else 403 `PDF_LOCKED`, also for past downloads after a downgrade; listing and clearing do not) (POST body is `HistoryIn`, a `GenerationSettings` plus company/job/content/style and the optional `pro_judge_model` (a `Model`) and `pro_rank` (1-4), so every generation setting is required and validated; the insert is built from the body's fields; listed entries have each setting or null for older rows), `GET /api/history/{id}/pdf`
- `app/routes/preview.py` - `POST /api/preview` (`{content_md, style}` -> `{html}`), the `render_html` document the PDF is made from
- `app/routes/preferences.py` - `GET/PUT /api/preferences`, `Preferences` model (style, tone, max_pages, notes, include_phone, include_graduation_year (default false), professional_years 1-50, earlier_years 0-50, model, optimization `light`/`smart`/`full` (default `smart`), pro_mode (default false), pro_models (2 to `PRO_MAX_MODELS` (4) distinct models, default `DEFAULT_PRO_MODELS`, which leaves out the default model); no judge setting: in Pro mode `model` judges; a model validator rejects duplicate pro_models and, when pro_mode is on, a `model` in pro_models (422); an older stored `judge_model` key is ignored; `Optimization` Literal must match `OPTIMIZATION_LEVELS` in `frontend/lib/api.ts`), `GenerationSettings` (the preferences that shape a resume, all required: model, optimization, professional_years, earlier_years, max_pages, tone, notes; `GENERATION_FIELDS` is its field names, matching `GENERATION_KEYS` in `frontend/lib/api.ts`), `generation_settings(prefs)`, `load_preferences` (applies `without_removed_models` first, so stored model ids no longer in `Model` load as the default AI model and are dropped from pro_models, topped up to `PRO_MIN_MODELS`; PUT still rejects them); new keys get defaults so older stored JSON still loads
- `app/pdf.py` - markdown -> HTML -> PDF (WeasyPrint), styles `professional`, `modern`, `classic`
- `app/ai.py` - OpenRouter client (`get_client` dependency, `Client` type), `Model` (Literal of selectable model ids; must match `MODELS` in `frontend/lib/api.ts`), `MODEL` default, `ask`, `ask_structured(client, messages, schema, model)` (Structured Outputs, `require_parameters`), `GET /api/ai/check` (2+2, default model)
- `app/prompt.py` - system prompt adapted from `docs/INSTRUCTIONS.md`; the resume rules are in `RULES` (shared with the Pro judge) and `context(baseline, job, prefs, year)` is the preferences, baseline and job block (also shared); `INSTRUCTIONS` is `HEAD` (role, task, steps, rules) plus `OUTPUT`; `PRO_CHAT_INSTRUCTIONS` is `HEAD` plus `PRO_CHAT_OUTPUT` (do not write the resume; `reply` and `ready`), used by `build_pro_chat_prompt`; `build_system_prompt(baseline, job, prefs)` is `INSTRUCTIONS` plus that context and adds a "User preferences" block (max pages, tone, notes, phone include/exclude, graduation year include/exclude, optimization level from `OPTIMIZATION`, experience windows). Step 4 and a Rules line make the generation defer to the optimization level; without that, Light polish rewrote the work history in 3 of 7 runs (0 of 12 after). `test_real_generation_follows_optimization_level` checks Light keeps the core bullets verbatim (dashes normalized: models swap in non-breaking hyphens) and the others rewrite. Rules from INSTRUCTIONS.md "Narrowing" are in `INSTRUCTIONS` (Rules) or, for the Earlier Experience format, in `experience_rules`; keep both in sync when INSTRUCTIONS.md changes. Earlier Experience entries must be Markdown list items: plain consecutive lines merge into one paragraph in the PDF. `experience_rules(prefs, year)` turns the year settings into concrete cutoff years in code (models are unreliable at date arithmetic); the route passes `date.today().year`
- `app/pro.py` - Pro mode. `write_candidates` runs `ask_structured` once per Pro model in a `ThreadPoolExecutor` (the route is a sync `def`, so the sync client is fine), each with `client.with_options(timeout=CANDIDATE_TIMEOUT)` and the last user message plus `WRITE_NOW`; a candidate that raises or returns no `resume_md` is logged and dropped, becoming a `ProFailure` (model, reason: "timed out after 300 s" for `APITimeoutError`, "failed with an error", "returned no resume"). `judge` shuffles the candidates, labels them A-D (no model names), and asks the AI model (`prefs.model`; `JUDGE_INSTRUCTIONS` with `RULES` and `context`) for a `Verdict` built by `verdict_schema(labels)`, whose `label` enum is only the labels in use (with a fixed A-D enum `gpt-oss-120b` ranked a non-existent "C" for two candidates in 2 of 3 runs, 0 of 4 after) (`ranking` best first: label, score, strengths, weaknesses, rule_violations; `rationale`); labels map back to models. `run_pro` returns a `ProResult` (`candidates` as `ProCandidate` best first, `rationale`, `judge_model`, `failed`); one candidate is returned unjudged (score None, judge_model None); with none, `candidates` is empty, `rationale` is `NO_CANDIDATES`, and the route returns no resume with that as the reply
- `app/ai.py` also has `PREMIUM_MODELS` (need the `premium_models` feature; keep in sync with `PREMIUM_MODELS` in `frontend/lib/api.ts`)
- `app/routes/generate.py` - `POST /api/generate`: first `check_access(plan, prefs, used, resets_at)`: Pro mode without `pro_mode` -> 403 `PRO_MODE_LOCKED`; a premium model (the AI model, and in Pro mode every Pro model) without `premium_models` -> 403 naming them; an allowance smaller than 1 (or, in Pro mode, the number of Pro models) -> 429 with the reset date; then a resume produced is recorded (`record_generations`: the AI model, or each Pro candidate that returned a resume). stored baseline + preferences (including `model`) + request job/message/history -> `{reply, company, experience_plan, resume_md}` plus the saved `GenerationSettings` used (`GenerateResponse`, added after the AI call; style, phone and graduation options are not included; `resume_md` null while asking questions). In Pro mode the AI model gets `build_pro_chat_prompt` and answers `ProChatResult` (`{reply, ready}`, no resume, so no output is wasted); not ready returns its questions with no resume and no company; ready calls `pro_turn`: `run_pro` with the normal writing prompt, then the response gets `pro` and the best candidate's `resume_md` and `company`, and `reply` becomes "<model> scored best (<score>/10). <rationale>" (`pro_reply`); `model` stays the AI model. Real tests check every model says ready when asked to generate and asks for a missing job description. `experience_plan` lists each baseline role with end year and section (professional/earlier/omitted) before the resume is written: without it the model leaked pre-cutoff roles in about 1 of 6 runs, with it 0 of 24. The frontend ignores it
- `static/` - built frontend, copied in by the Dockerfile (git-ignored; override with `STATIC_DIR` env)
- `tests/` - pytest; `conftest.py` sets env before app import and provides `client` (fresh temp db per test) and `signed_in` fixtures

## Rules

- Always `uv run ...` and `uv add ...`; never pip or bare python
- All API routes live under `/api`
- Every data route takes `UserId` and filters by it
- Raw SQL via stdlib `sqlite3`; no ORM
- Config from environment: `OPENROUTER_API_KEY`, `DB_PATH` (default `data/jobfit.db`), `STATIC_DIR`, `CLERK_SECRET_KEY`, `CLERK_AUTHORIZED_PARTIES` (comma-separated origins, default `http://localhost:8000`)
- Tests override `auth.current_user` and `plans.current_plan` for data routes (the `signed_in` fixture is on Pro with every feature; `on_plan(key, *features)` switches plan; `tests/test_billing.py` covers access and limits); `tests/test_auth.py` signs real RS256 tokens with a local key to test verification without network
- When changing the prompt, run the `integration` tests a few times: they check real output against the resume rules. `test_real_generation_with_each_model` calls every selectable model (includes Opus; costs a few cents); select with `-k each_model`
- `tests/test_pro.py` fakes each model and the judge separately (`FakeAI`); a `threading.Barrier` proves the candidates run in parallel. Its integration tests run a real Pro round (default Pro models, the default AI model judging, about 30 s) and check the judge flags a planted invented role
- Unit tests never call OpenRouter: override `ai.get_client` via `app.dependency_overrides`
- Short modules and functions; no defensive code; no emojis

## macOS setup

WeasyPrint needs Pango: `brew install pango`. Because `uv` is a hardened-runtime binary, macOS strips `DYLD_*` variables, so Python cannot find Homebrew libraries by default. `tests/conftest.py` sets `DYLD_FALLBACK_LIBRARY_PATH` for tests; for the dev server pass it with `--env-file` (a file containing `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib`).

## Commands

- `uv run pytest` - tests (real-API tests are marked `integration` and skipped by default)
- `uv run --env-file ../.env pytest -m integration` - real OpenRouter tests
- `uv run --env-file <mac.env> uvicorn app.main:app --reload` - dev server on macOS
